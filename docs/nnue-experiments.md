# NNUE experiments

The lab notebook for nets: one row per experiment, one variable changed per
experiment, validation loss recorded before any CI games are spent. Results
that did not follow this protocol are listed separately and are **not
evidence** for or against an idea.

## Protocol

1. **Hypothesis and one variable.** Write down what changes (data, epochs,
   width, buckets, loss, LR, ...) and what stays fixed. If two things change,
   it is two experiments.
2. **Validation loss first.** Every run uses `--val` on the fixed held-out set
   below and reports float and quantised validation loss per epoch. A
   candidate that does not beat the incumbent's validation loss (scored with
   `nnue-trainer eval` on the same set) does not get CI games unless the
   experiment is specifically about a game-only effect (e.g. NPS cost).
3. **Games decide.** Same-shape nets: `net-gate` (5+0.05, [0, 10]) or `stc`.
   Shape changes that cost NPS (wider H, more buckets): `stc` (10+0.1,
   [0, 5]); the shorter gate overweights the speed loss.
4. **Bootstrap rule** (kept from v1): only a merged net generates the next
   dataset.
5. **Record everything here**, including failures, with the exact command.
6. Every trained net gets an experiments.jsonl row committed to main when
   training finishes (netloop record), whatever the gate result; the
   dashboard shows gate status from the queue log automatically.

### Fixed validation set

`val.bin`: the last 1,000,000 positions of seed 9 (net4 self-play, 8000
nodes), removed from the seed-9 training file. Positions come from games the
nets never trained on. Labels: `lambda = 0.5`.

## Audit of the v1 chain (2026-11-06)

What held up:

- net1 -> net4 were real gains, each SPRT'd against the then-current main
  (+51, +149, +40, +13). Main stays on net4.
- Inference is correct (the trainer reproduces its formula; bench/evalhash
  stable through the refactors) and the SIMD work was sound.
- The bootstrap rule (no data from ungated nets) was right.

What did not:

- **No validation loss, ever.** Every decision was a game result, often small
  (200-1800 games), and several were drawn from a single run.
- **Confounded experiments.** net7 changed the loss, the data mix and mirror
  at once; net8 changed data size (7.7M), node count (5000) and epochs; net13
  changed the label source and size (500k positions, 38 epochs). None of these
  can be attributed to one cause.
- **Gross undertraining.** v1 trained each net from scratch for ~2 epochs on
  one generation's ~80M positions on a 2-core VPS, discarding the previous
  generations. Strong nets of this shape are typically trained on billions of
  position-samples with a decaying LR. The "256 is saturated" conclusion came
  from one 200-game local match (CI -41..+31) and does not follow.
- **512-wide was tested undertrained.** One from-scratch run on 77M x 2
  epochs with the old loss (-30 at stc). A wider net needs *more* training
  than a narrow one, so this says nothing about capacity.
- **The trainer had no clipping while training**; output weights were
  clipped after the fact (net10b) which shifts the output distribution.
- **Teacher labels (net13)** used Stockfish evals as targets: -502 Elo, almost
  certainly a units/scale error. Distilling Stockfish is also off-brief for a
  project whose goal is to beat it with its own engine; do not repeat it.

## Conclusions to date (2026-11-07)

Rows in `net/experiments.jsonl`; gate results in the queue log.

- **Data is the lever.** g4 (from scratch on pool4, 730M, +35% data vs g3,
  same recipe) **+26.7 [10.1, 43.5]** at the net gate. Gen 5 (pool5, 976M,
  +34%) is trained; its validation-loss gain over g4 is smaller than g4's
  over g3; its gate
  candidate is g5kb8m (no `g5` row in `net/experiments.jsonl` yet).
- **Eval-scale hypothesis rejected.** g3f vs g3fs (x0.92) +1.4 vs -8.9; g4ws
  (g4w at g3's scale) still -22.7. Screen on best-scale loss
  (`eval --best-scale`), not raw loss.
- **Short warm starts on new data don't win** (g4w -21.7, over-specialised;
  auto-loop fine-tunes never beat the champion). The auto loop only ingests.
- **Lambda 0.3 rejected** (g4l3 -8.8, inconclusive; its loss is
  lambda-biased, so it was gated on games).
- **King buckets:** from scratch they are data-limited (gap 0.0011 at 50% of
  the games vs 0.0006 at 100%, overfits from epoch 1), but an **exact
  factoriser warm start from the champion wins**: kb8m (via g4m1) beats kb4
  and the plain fine-tune control g4ft on val.bin and val17x2;
  **g4kb8m merged +11.0 [4.9, 17.1]**.
- Validation loss differences of a few 1e-4 have not predicted gate Elo on
  their own: games remain the gate.

## Running a generation with scripts/netloop.py

`scripts/netloop.py` (stdlib only) sequences one generation on the laptop.
Data lives in `~/rustfish-data` (`--data-dir`), with the fixed `val.bin`
there; the trainer is `tools/nnue-trainer/target/release/nnue-trainer`
(`--trainer`). Every step is safe to rerun.

```bash
# 1. Pull a finished datagen run (skips if s11.bin exists).
python3 scripts/netloop.py fetch --run <datagen run id> --seed 11
# 2. Shuffle the pool. Seed 7 is refused unless --force.
python3 scripts/netloop.py pool --out pool7.bin --seeds 4,5,6,8,9,10,11
# 3. Train. Unknown flags (--lr, --lr-end, --batch, --threads, --checkpoint, ...)
#    go straight to `nnue-trainer train`; output is <name>.bin + <name>.log.
python3 scripts/netloop.py train --name E2 --pool pool7.bin --hidden 256 --buckets 1 --epochs 6
# 4. Only if val loss beats the incumbent: branch nnue-E2 off origin/main, copy
#    the net, set H/BUCKETS, build, perfttest + selftest 100, bench, commit
#    with the Bench: trailer, push. Prints the queue command (net-gate for
#    same-shape nets, stc when H or BUCKETS change); --queue also runs it.
#    Then it writes E2's net/experiments.jsonl row (shape, epochs, positions,
#    final val loss + quantised, mean|eval|, parsed from E2.log) and pushes it
#    to main as a data-only commit (fresh fetch, retry once on a race, never
#    forced; same id = update in place). --no-record skips that; --best-scale
#    also records `nnue-trainer eval --best-scale` (off by default).
python3 scripts/netloop.py embed --name E2 --net ~/rustfish-data/E2.bin --hidden 256 --buckets 1 \
    --baseline E1 --seeds 4,5,6,8,9,10,11 --notes "one variable: + seed 11"
# 5. A local-only experiment (never branched) gets the same row, branch local-<id>:
python3 scripts/netloop.py record-local --name g3kbf --baseline g3f --notes "kb8m + factoriser"
# 6. When the queue reports, fill in the games.
python3 scripts/netloop.py record --name E2 --sprt-elo 4.1 --sprt-ci 0.8,7.4 --sprt-games 6144 --verdict merged
```

`net/experiments.jsonl` is the machine-readable twin of the table above:
one JSON object per experiment (`id, date, hidden, buckets, seeds, epochs,
positions_per_epoch, val_loss, val_loss_quantized, baseline, branch, notes,
sprt, verdict`, plus `king_buckets, mean_abs_eval, best_scale_val,
best_scale_factor, output_scale, train_data, init` when known). `netloop
auto` embeds through `embed`, so its winners are recorded too (baseline
`main@<net blob>`; `auto --no-record` / `--best-scale` pass through).
`record` still edits only the local file (use it for --sprt-*/--verdict). Bucketed nets (`--buckets > 1`) need a base with the
`BUCKETS` constant (`--base origin/nnue-arch` until that lands); `embed`
refuses otherwise.

### King-bucketed inputs

Both trainers take `--king-buckets <none|m1|kb4|kb4m|kb8m>` (see
`tools/nnue-trainer/README.md`); `--init` from a one-bucket net copies its
rows into every bucket. To embed a bucketed net, pass the same layout to
`netloop.py embed --king-buckets <layout>` (it sets `KING_LAYOUT` in
`src/nnue.rs` and treats it as a shape change, so it gates at `stc`). First
measurement: about -14% bench NPS for kb8m at H = 256.

`--factorise` (both trainers, KB > 1) trains a shared 768-row block added
to every bucket and merges it into the exported net (format and engine
unchanged); `--wd-active-only` (default on for KB > 1) restricts AdamW
decay on bucketed FT rows to rows seen in the batch. Train factorised
nets from scratch, or warm-start them from a plain net with `--factorise
--init plain.bin` (`F` = its rows, buckets 0): exact for kb4 from a `none`
net (g4: start 0.026672 / quantized 0.026673 = g4's loss on val 100k), but
a mirrored layout cannot start exactly from an unmirrored one-bucket net
(kb8m from g4 starts at g4-as-m1, 0.028718; see
`tools/nnue-trainer/README.md`). `--keep-best` makes `<out>` the best
quantised-val epoch (start included), since warm-started kb runs peak early.

## Overnight loop: `netloop.py auto`

`python3 scripts/netloop.py auto` repeats every `--interval` s (1200):

1. **Ingest.** Completed `datagen.yml` runs (generator ref `main` only) not in
   `~/rustfish-data/ledger.json` are downloaded and converted into
   `~/rustfish-data/auto/`; growth of `local/L*.txt` (complete lines only,
   byte offsets in the ledger) is converted in >= 64 MB chunks. Each file is
   `scalecheck`ed against origin/main's net: slope in [0.40, 0.65] -> an x2
   copy is trained on (raw deleted), [0.80, 1.25] -> used as is, anything else
   -> quarantined and logged. The first run records every existing CI run and
   the hand-converted part of each `L*.txt` (records in `<stem>[a-z].bin`) as
   pre-existing; `--adopt <file>` counts an existing net-scale file as new.
2. **Train** once >= `--threshold` (30M) new positions arrived since the last
   attempt and no other `nnue-trainer* train` runs: the data since the last
   embedded net (newest first, <= 120M) + an equal slice of `--replay-pool`
   (pool3f.bin, rotating offset), shuffled; GPU warm start from main's net,
   same H/B/king layout, 3 epochs, lr 2e-4 -> 1e-5.
3. **Screen** with `nnue-trainer eval` on `val.bin` and `fix/val16x2.bin`.
   Better than main on both -> `netloop.py embed` (branch `nnue-auto-<n>`,
   pushed) and `queue.py add nnue-auto-<n>:net-gate` (`--expect` = 10 x the
   smaller relative improvement in %, 2..10, if queue.py supports it).

Logs: `~/rustfish-data/netloop-auto.log` and `netloop-auto.jsonl`. It never
commits to main and writes nothing outside `auto/`, the ledger and its logs.
`--dry-run` does step 1 for real and prints what 2 and 3 would do.

Fixed-scale screening (off by default): `auto --screen-scale match
[--scale-val val.bin]` rescales each candidate to main's eval scale
(`nnue-trainer rescale --match`, slope normaliser) before screening and
embeds the scaled net. `embed --match-scale <ref.bin|base>` does the same
for a hand-embedded net. Tests: `python3 scripts/test_netloop.py`.

## CI training sweeps (`train-sweep.yml`)

Parallel one-variable experiments on the GitHub runners: `prep` builds one
pool and both validation sets and uploads them as one artifact; every
variant job downloads it and trains with `--threads $(nproc) --keep-best`;
`report` puts every variant in one table in the run summary. Helpers:
`scripts/train_sweep.py`.

- **Pool.** `seeds`: JSON list of seeds, `"A-B"` ranges or `"all"` (the
  newest successful `datagen.yml` run of each seed; ranges skip seeds with no
  run), or `{seed: run id}`. Seed 7 is quarantined (an error if named,
  skipped in ranges). Seeds 14-18 (`x2_seeds`) get every score doubled,
  saturating, as `fix/x2.py`; seeds >= 19 are net scale. `positions`
  (default 300M) caps the pool: every seed contributes the same fraction, as
  evenly spaced 64k-record blocks, then the trainer's `shuffle` mixes them.
  The manifest (runs, positions per seed, x2) is in the run summary.
- **Validation.** `val.bin` = the last 1M positions of seed 9 and `val17x2`
  = the last 1M of seed 17 with x2: the laptop's `val.bin` and
  `fix/val17x2.bin` (sha256 checked, `matches_laptop` in the manifest). Both
  are cut from their seeds before sampling, so they are never trained on
  (seeds 9 and 17 are always fetched for them). `--val` (so `--keep-best`)
  is `val.bin`.
- **Size limit.** The pool is 32 bytes/position: 300M = 9.6 GB, which every
  variant job downloads (test run: 640 MB in 11-47 s, so ~3-12 min for
  300M). Hosted runners have ~70 GB on
  `/mnt`; `prep` needs the gzip artifacts (~12.5 B/position over every
  fetched seed) + ~2x the pool, so ~1B positions (32 GB) is the most one
  runner can build, and it would cost every variant ~10+ min of transfer.
  Keep sweeps at <= 300M: rank variants there, train the winner on the full
  pool locally.
- **Warm start.** `init_net`: `<ref>:<path>` (e.g. `main:net/nnue.bin`), an
  https URL, or `run:<run id>:<artifact>:<file>` (a previous sweep's net).
  It is passed as `--init` to every variant unless the variant has
  `"init": false`; `init_args` (default `--buckets 8`) is its shape, for the
  reference row. King-bucket variants add e.g. `--king-buckets kb4
  --factorise`. Mirrored layouts (kb4m, kb8m) start exactly only from an
  `m1` net; from main's `none` net they start at `eval --king-buckets m1`
  of it (trainer README).
- **Time.** `train_minutes` (default 320) stops the trainer inside the 6 h
  job limit; the best finished epoch is the output and the checkpoint is
  uploaded (`--resume` it locally). Set `--epoch-size` so epochs end often
  enough to lose little at the limit. 320 min at 0.8M pos/s is ~15B
  position-samples.
- **Table.** Sorted by best-scale loss on val.bin + val17x2 (`eval
  --best-scale`, scale profiled out) of the output net; when `--keep-best`
  kept an earlier epoch (or the start net, e0), the last epoch's best-scale
  losses are shown too. Also final and best epoch val (float/quantised),
  the start loss, pos/s and the runner CPU (`lscpu`). The init net is a
  reference row. The CPU only changes speed: the trainer is bit-identical
  across ISAs and thread counts.
- **Runners.** A sweep shares the 20 runners with the queue. With the
  `lanes` in `scripts/queue-settings.json` (13 background datagen + 6
  foreground + 1 queue job) `max_parallel` 6 (default) takes the whole
  foreground lane, so SPRTs wait behind it. Dispatch when the queue is
  light, or lower `lanes.background_parallel` for the duration; never set
  `max_parallel` above the foreground lane.

```bash
gh workflow run train-sweep.yml -f name=kb-warm -f seeds='["8-29"]' -f positions=300000000 \
  -f init_net=main:net/nnue.bin -f variants='[
  {"name":"plain","args":"--hidden 512 --buckets 8 --epochs 4 --lr 2e-4 --lr-end 1e-5 --mirror"},
  {"name":"kb4","args":"--hidden 512 --buckets 8 --king-buckets kb4 --epochs 4 --lr 2e-4 --lr-end 1e-5 --mirror"},
  {"name":"kb4f","args":"--hidden 512 --buckets 8 --king-buckets kb4 --factorise --epochs 4 --lr 2e-4 --lr-end 1e-5 --mirror"},
  {"name":"kb4mf","args":"--hidden 512 --buckets 8 --king-buckets kb4m --factorise --epochs 4 --lr 2e-4 --lr-end 1e-5 --mirror"},
  {"name":"kb8mf","args":"--hidden 512 --buckets 8 --king-buckets kb8m --factorise --epochs 4 --lr 2e-4 --lr-end 1e-5 --mirror"},
  {"name":"kb8mf-wd","args":"--hidden 512 --buckets 8 --king-buckets kb8m --factorise --wd 0.01 --epochs 4 --lr 2e-4 --lr-end 1e-5 --mirror"}]'
```
